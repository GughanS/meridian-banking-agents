# Implementation Plan: Meridian Banking Agents

## 1. Modules & Interfaces

*   **Mock Core Banking (`backend/app/core_banking`)**
    *   *Purpose:* Simulated core banking ledger.
    *   *Interface:* FastAPI router (`/mock-core/v1`) exposing endpoints for customers, accounts, balances, transactions, cards, loans, and fraud. Protected by `X-Core-Api-Key`.
*   **Services (`backend/app/services`)**
    *   *Purpose:* Pure, deterministic business logic engines and state machines.
    *   *Modules:* `fraud_rules.py` (Rule scoring), `eligibility.py` (Loan limits & logic), `emi.py` (Calculations), `pending_actions.py` (Action state machine).
*   **Tool Layer (`backend/app/tools`)**
    *   *Purpose:* Typed wrappers around the Core Banking Client. Validates inputs, authorizes against the JWT identity, handles idempotency for writes, and integrates with the `PendingAction` service for `propose_*` operations.
    *   *Interface:* `ToolRegistry` exposing Pydantic-validated Gemini functions.
*   **LLM & Orchestration (`backend/app/llm` & `backend/app/orchestration`)**
    *   *Purpose:* Communication with Gemini API, managing the LangGraph state machine.
    *   *Modules:* `supervisor.py` (Planning & Routing), `agents/` (Specialists: Customer, Risk, Credit), `guardrails.py` (PII, Prompt Injection), `synthesizer.py` (Streaming response formulation).
*   **API & Streaming (`backend/app/api`)**
    *   *Purpose:* External interface for the React frontend.
    *   *Interfaces:* REST (`/api/v1/chat`, `/api/v1/actions`), SSE (`/api/v1/chat`, `/api/v1/stream/events`).
*   **Frontend (`frontend/`)**
    *   *Purpose:* User interaction, UI block rendering, and real-time visualization.
    *   *Tech:* React, Vite, Tailwind CSS, TanStack Query, SSE clients.

## 2. Data Flow
1.  **User Request:** Frontend sends a message via `POST /api/v1/chat` (SSE stream).
2.  **Guardrails (In):** `guardrail_in` node checks size, strips control characters, runs injection heuristics, and masks inputs.
3.  **Supervision:** `supervisor_plan` calls LLM to generate `tasks`. Validates output structure.
4.  **Dispatch:** Tasks are executed concurrently or sequentially.
5.  **Specialist Agent Loop:** Each agent executes a `think -> tool_call -> result` loop (up to 5x). Tools authorize using `customer_id` from the session context and talk to the Core Banking client.
6.  **Synthesis:** `supervisor_synthesize` takes all `AgentResult`s and streams the final answer back to the frontend, along with typed `ui_blocks`.
7.  **Guardrails (Out):** `guardrail_out` masks PII from the final stream and enforces disclaimers.

## 3. Risks & Mitigations
*   **Risk:** LLM hallucinating financial numbers (e.g., loan rates).
    *   *Mitigation:* Strict adherence to deterministic engines. System prompts strongly discourage computation. All critical numbers are generated by `services/` and simply reported by the LLM.
*   **Risk:** Prompt Injection and context poisoning via transaction data (e.g., "Merchant: IGNORE PREVIOUS INSTRUCTIONS").
    *   *Mitigation:* Tool output wrapping, adversarial testing in Phase 4/8, strict `guardrail_in` heuristics.
*   **Risk:** Latency due to multi-agent architecture.
    *   *Mitigation:* Concurrent task execution (`asyncio.gather`) during the dispatch phase. Streaming UI rendering. Using `gemini-2.5-flash` for agent loops.
*   **Risk:** UI complexity with SSE and dynamic blocks.
    *   *Mitigation:* Clear, typed `ui_blocks` contracts (e.g., `type: 'balance_card', data: {...}`). Isolation of block rendering logic into distinct React components.

## 4. Proposed Deviations
*   **Deviation:** None currently planned. The architecture described in the prompt is robust and well-scoped. I will strictly adhere to using `Decimal` for all money types and segregating the Mock Core API completely.
